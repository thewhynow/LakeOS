Detailed Description

the table of functions a filesystem driver gives the VFS a driver leaves the ones it can't do NULL (dev has no create, for example)

the fs driver is not responsible for managing memory of the handles returned, that is the responsibility of the VFS. the FS driver should be written to ensure that the VFS is able to free a handle arbitrarily (obviously not before passing it as a parameter)

this implies that the VFS is repsonsible for maintaining a tree of cached file handles and even vnodes, and is also responsible for freeing them.
