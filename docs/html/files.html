dma.h		Isa dma controllers, two of them: controller 0 has channels 0-3, controller 1 has 4-7 (4 is the cascade, can't be used) only the floppy uses it
    
elf.h		32 bit elf, the structs and constants straight from the spec, and the loader that puts an executable into a process
    
exe.h		Processes, there is no scheduler: they form a stack and exec pushes onto it, exit pops it
    
fat.h		Fat12/16/32 driver, a vfs driver (see FAT_init). on-disk structures are only visible inside the driver (FAT_H_INTERNAL), everything else gets opaque pointers and the FAT* api at the bottom
    
fdc.h		Floppy disk controller, 1.44MB 3.5" drives only, reads and writes go through a one sector buffer using dma (dma.h)
    
gdt.h		Global descriptor table. flat segments, layout is: null, kernel code (0x08), kernel data (0x10), user code (0x18), user data (0x20), tss (0x28)
    
idt.h		Interrupt descriptor table
    
io.h		X86 port io (in/out instructions)
    
irq.h		Hardware interrupts (IRQ0 - IRQ15)
    
isr.h		Cpu exceptions + software interrupts (the isr stubs in asm/isr.s)
    
kmm.h		Kernel heap, first-fit allocator over a doubly linked free list. lives at HEAP_START and pages are demand-mapped by the page fault handler
    
multiboot.h		What the multiboot bootloader (grub) hands the kernel
    
pic.h		8259 programmable interrupt controller (master + slave)
    
pit.h		Programmable interval timer (channel 0), also keeps the wall clock in rtc.h ticking
    
pmm.h		Physical memory manager, one bit per 4KB block returns PHYSICAL addresses
    
ps2.h		Ps2 keyboard (scancode set 1) and the stdin buffer it fills
    
rtc.h		Cmos real time clock, read once at boot. after that the pit keeps time ticking (see pit.h)
    
sal.h		Storage abstraction layer, the common interface the ata and floppy drivers sit behind, and what filesystems read through
    
sys.h		Syscalls, userspace gets here with int 0x80. each sys_* is the kernel side of one, the handler unpacks the registers and puts the result in eax
    
tss.h		Task state segment, only here so the cpu knows which stack to use when an interrupt comes in from ring 3
    
tty.h		Text mode terminal (80x25 vga buffer)
    
umm.h		User memory manager, keeps track of what is mapped in a process's address space (0x0 - 0xC0000000) as a list of blocks sorted by address
    
vfm.h		Virtual file manager, an in-memory filesystem (a vfs driver) the root is one flat directory, and a file's contents are a kmalloc'd buffer
    
vfs.h		Virtual filesystem, the one api for every filesystem driver (fat, vfm, dev). paths start at the root fs and drivers are attached as vnodes. the user only ever sees file descriptors
    
vga.h		Vga text mode colors and cell packing
    
vmm.h		Virtual memory manager, 32-bit two level paging (4KB pages, and 4MB ones). the kernel lives in the top 1GB (0xC0000000 up), user stuff below it, see umm.h
